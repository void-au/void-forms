# SPR_001 - Foundation And MVP API

## Sprint Goal
Ship a working MVP of Void Forms with one endpoint (`/v1/forms`), Turnstile verification, site-based validation rules, rate limiting, and Telegram notifications.

## Status
Completed in repository with implementation, tests, and setup docs.

## Delivered

1. Project skeleton
- Added `app/`, `app/api/`, `app/services/`, `app/models/`, `app/core/`, `tests/`, `config/`, `data/`.
- Added `requirements.txt` and `.env.example`.
- Added FastAPI app entrypoint and `GET /health`.

2. Configuration model
- Added `config/sites.yaml` as source of truth for sites.
- Added typed models for site config and validation rules.
- Added startup config loading via `SiteRegistry`.

3. Database for expandable data
- Added MongoDB submission storage (`app/services/submission_store.py`).
- Stores submission payload as flexible documents for expandable fields.

4. API endpoint
- Added `POST /v1/forms` in `app/api/forms.py`.
- Enforces site lookup, rate limit, Turnstile check, validation, persistence, and Telegram notification.

5. Turnstile integration
- Added server-side verifier with Cloudflare endpoint.
- Handles timeout and HTTP errors.
- Supports local bypass via `TURNSTILE_BYPASS=true`.

6. Rate limiting
- Added in-memory fixed-window limiter with configurable window and request cap.

7. Telegram integration
- Added bot notification service.
- Notification failures are returned as warnings without dropping accepted submissions.

8. Error handling and observability
- Added request ID middleware.
- Added consistent API error responses via centralized exception handlers.

9. Tests
- Added tests for:
  - happy path
  - invalid site
  - disallowed attributes
  - Turnstile failure
  - rate limit exceeded
  - Telegram failure behavior

10. Documentation
- Expanded `README.md` with setup, run, env vars, and curl examples.

## Follow-ups

1. Set real Turnstile secrets in `.env` (for example, `TURNSTILE_SECRET_DEMO_SITE`) referenced by `config/sites.yaml`.
2. Set real `TELEGRAM_BOT_TOKEN` and chat IDs.
3. Add persistent/shared rate limiter backend (Redis) for multi-instance deployments.
4. Add CI workflow for automated tests.
